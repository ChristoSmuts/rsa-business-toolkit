# 0003: MiniSearch for client-side search

- Status: accepted
- Date: 2026-09-15

## Context

Search must work on GitHub Pages with no server, in English and Afrikaans now and in all eleven official languages later. Results must deep-link to a heading and be filterable by section, entity type and business type. Glossary terms, checklist items and common questions should appear as their own result types.

## Options considered

- **Pagefind.** Indexes built HTML, strong for plain page search. It offers stemming only for languages it supports and does prefix matching, not fuzzy matching. Typed results such as tasks and glossary entries would need workarounds.
- **MiniSearch.** Indexes structured JSON that we already generate. Supports prefix and fuzzy matching, field boosts and filters, and can be tested in Vitest without building the site.

## Decision

Use MiniSearch 7. Build one serialised index per language at build time from `src/data/<lang>/`, with a content hash in the filename. Load it only when the reader first opens search.

## Consequences

- None of the South African languages other than English has a stemmer in either tool. Prefix plus fuzzy matching is the practical approach for all of them.
- Each index has a size budget of 400 KB gzipped, enforced by a test. If a language exceeds it, the index is split by section.
- No WebAssembly is needed, so the CSP does not need `wasm-unsafe-eval`.

## Implementation notes (WP-33, 2026-10-02)

- **Where the file name lives.** `pnpm search:build` (`scripts/build-search-index.ts`, run by `pnpm build` before `astro build`) writes `public/search/<lang>.<hash>.json` and records the names in the gitignored `src/generated/search-index.json`, which pages read at build time (`src/lib/search/files.ts`). The plan put the hash in `manifest.json`, but that file belongs to `content:build` and is drift-checked, so a later step cannot write to it.
- **Shared options.** A serialised MiniSearch index does not carry its functions, so the tokenizer, `processTerm`, prefix and fuzzy rules live in one module (`src/lib/search/options.ts`) that the build and the browser both import. The tokenizer keeps form codes whole (`VAT264`, `14.3`, `R120,000`) and adds a joined alias for a code written with a space (`SAPS 601` → `saps601`); `processTerm` folds case and diacritics and drops a short English and Afrikaans stop-word list.
- **Ranking.** BM25 `b` is 0.3 instead of MiniSearch's 0.7, and checklist items weigh 1 instead of A7's 1.5. With the defaults, one-line checklist items that only name `VAT264` pushed the section that explains the form out of the top three, which A7's own test forbids. A "Words used" term that the glossary also defines is left out, and a term opens the first section of its page that uses it. Two entries that open the same place are shown once.
- **Queries (review WP-33 pass 1).** The index-time alias alone made a spaced code stricter: `VAT 264` needed `vat`, `264` and `vat264` all at once. A query is now built as a MiniSearch query tree: letters followed by a number (any case) and hyphenated words become "both words, or the joined form". The index also joins hyphenated words (`e-filing` → `efiling`). The `OR` fallback leaves out lone numbers and single letters, and a query is cut to 12 words.
- **Queries (review WP-33 pass 2).** Searching "both words, or the joined form" added the scores of the two branches (the sources register outranked the section that explains `VAT264`) and fuzzy-matched the joined form (`page2` matched every "page"). Now each pair is resolved against the index first (`resolvePairs`): the joined form alone, exactly, when the index holds it; both words otherwise. A stop word before a number pairs only in capitals.
- **Queries (review WP-33 pass 3).** Resolving hyphenated pairs to their exact joined form, like codes, cut `BTW-registrasie` to 9 results against 21 for `BTW registrasie`, and shrank results as a word was finished. Only code pairs (letters then a number) are resolved now; a hyphenated pair is "both words, or the joined form exactly". Unit tests on both real indexes require a hyphenated query to find at least what the spaced one finds.
- **Queries (review WP-33 pass 4).** Every pass so far found a major in query handling, each fixed for its case. Pass 4 found that a term holding a digit was fuzzy-matched like a word, so `EMP501` found `EMP201` and `R500,000` found `R750,000`. The fix is for the class: one rule per kind of term (`matchRule`), written down as a table in `docs/design-system.md` ("Search", "Queries") and tested row by row on both real indexes. A term with a digit is never fuzzy, a bare number is exact, and a code or an amount is prefix-matched only while it is being typed; a resolved spaced code follows the same rule as the joined spelling. Counts are true totals, and the search page lists every result.
- **Queries (review WP-33 pass 5).** Pass 5 found three gaps in the table itself. A spaced pair resolved to its joined code found less than its two words (`VAT 15%`, `brand 5`, `under 100`), so a spaced code is now searched both ways, joined first, and never finds less than its words; the joined form is prefix-matched while the number is typed (`SAPS 60` reaches `SAPS601`). South African amounts and tax years have one spelling, the same at index and query time (`R120 000` = `R120,000` = `R120000`; `R2,3` = `R2.3`; `R2.3 miljoen` also indexes `R2300000`; `2026/27` = `2026/2027`). A hyphen chain keeps its words without stop words (`pay-as-you-earn` finds PAYE). Enter, the search page and the 404 suggestions read a query as finished, so `R1` does not open `R146`.
- **Queries (review WP-33 pass 6).** Six passes each found a major in query handling, and pass 6's first was a regression from the pass 5 fix for Enter. Special cases were replaced by two standard rules. Enter acts on what the reader sees (the ARIA combobox pattern): it opens the active option or the first one and never starts a different search; only a list that belongs to older text makes it wait for the current text's search, the same one the live list runs. Every query is "all words first, then any word": results that match every part come first, then always the results that match some words, so `EMP201 deadline` lists the EMP201 glossary entry after the one page naming both. The re-search on Enter and the any-word-only-when-nothing-found fallback were deleted. A spaced pair ranks its joined reading first only when the joined form names a glossary or "Words used" entry; otherwise its readings are merged by score, so `VAT 15%` opens the VAT entry. `R1m` and `2026-27` are read as `R1 million` and `2026/27`, a short year counts only when it is the next year, and a match through the millions alias is marked.
- **Queries (review WP-33 pass 7).** The two rules stay. Documents now carry a weight next to the kind's (`DOC_WEIGHT`): "How this was made" and "What has changed" are about the guide and weigh a quarter, and their entries never lead as all-words results, so `PAYE deadline` opens the PAYE entry rather than the corrections log. An option highlighted with an arrow key wins on Enter even in an older list; after the results code failed to load, Enter submits to `/search/?q=` again; "See all" passes `typed=1` so the search page lists the promised results; counts say how many results match every word.
- **Queries (review WP-33 pass 8).** Pass 7's document weight hid the pages about the guide from readers who asked for them by name (`how this was made` 6th, `wat het verander` not in the dialog). The demotion now depends on the query: an entry of those pages whose own heading holds every word leads; one that names the words only in passing weighs a quarter (applied by the client, no longer stored in the index) and ranks with the any-word results. Results carry `allWords`, and the count of results matching every word includes those pages.
- **Queries (review WP-33 pass 9).** Pass 8 forced any about-the-guide entry whose heading held every word to the front, and the changelog's headings name other pages, so `register`, `name` and `branding` opened editing notes. Now those pages weigh a quarter in every search, and only a query that asks for the page by its title (every word in the title, covering more than half of it) makes the page's first section lead. An entry whose heading holds every word keeps its weighted place among the all-words results; one that names the words only in its text ranks with the any-word results. The count of results that match every word is the block listed first.
- **Queries (review WP-33 pass 10).** The pass 9 title rule knew only the navigation title, not the H1 a page shows ("AI disclosure", "Changelog and redline"). It is now one rule for every page, and the special case for the two pages about the guide is gone: the first entry of every page carries both titles in the title field (and the H1 as a stored field), and a query whose words are all words of either title, covering more than half of it, leads with that page; with two such pages, the one covered most, then the first in reading order. Words count whole, and only the last word of a longer query, while typed, may be the beginning of one (from four letters). `has`, `have` and `had` do not count, as `het` does not. Within the all-words results, an entry whose heading holds every word comes before one whose text does; the pages about the guide keep only their quarter weight and the body-text demotion.
- **Queries (review WP-33 pass 11).** The heading lift counted prefix and typo matches (`stall` for "small"), so it now uses a heading-only query of whole words, with the typed last word's beginning from four letters, and a result that needs a typo match counts half its score against results that hold every word as written. The H1 moved from the first entry's heading field to its breadcrumb, so a page title lifts a page only through the title rule (`quote template` opens the Quotation template again). A typed one-word title leads after another typed word, stop words included (`wat het verand`).
- **Size.** 165.6 KB gzip in English (945 entries) and 182.3 KB in Afrikaans (951 entries, all translated), well under the budget; no sharding.
