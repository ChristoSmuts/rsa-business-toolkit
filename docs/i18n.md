# UI strings and languages

This page explains how the app's interface text works in English and Afrikaans, and how to add strings or a new language. The 36 documents are content, not UI strings. Their translation workflow is in `docs/build-plan.md` Part A6.

## Files

| File                               | What it holds                                                                                                                           |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `src/i18n/locales.ts`              | The 11 official South African languages: code, names, `hreflang`, direction, status, flags                                              |
| `src/i18n/en.json`                 | Canonical UI dictionary. Every key starts here                                                                                          |
| `src/i18n/af.json`                 | Afrikaans UI dictionary. Exactly the same keys as English                                                                               |
| `src/i18n/index.ts`                | `t`, `useTranslations`, `pick`, `getDictionary`, `createTranslator`, `formatDate`, `formatRand`, `formatNumber`, generated `ParamNames` |
| `src/lib/i18n-routes.ts`           | `localeStaticPaths`, `alternateUrls`, `switchLocaleUrl`                                                                                 |
| `src/lib/paths.ts`                 | `href()` and path parsing. Takes its locale list from `locales.ts`                                                                      |
| `astro.config.ts`                  | `i18n.locales` and sitemap `i18n.locales` are derived from `locales.ts`                                                                 |
| `tests/unit/i18n.test.ts`          | Dictionary parity and text rules, locale metadata, `t` behaviour, parameter types                                                       |
| `tests/unit/format.test.ts`        | `formatDate`, `formatRand`, `formatNumber`                                                                                              |
| `tests/unit/i18n-routes.test.ts`   | Route helpers                                                                                                                           |

## Locales

`LOCALES` in `src/i18n/locales.ts` is the only list of languages. Everything else derives from it:

- `enabled: true` means the locale is routed and built. Only `en` and `af` are enabled.
- `ENABLED_LOCALES` is `['en', 'af']`. The type `Locale` is `'en' | 'af'`. `LocaleCode` is any of the 11 codes.
- `DEFAULT_LOCALE` is `en`. English URLs have no prefix, other locales get `/<code>/`.
- `status` describes the documents: `complete` (English), `partial` (Afrikaans, machine translated, not yet reviewed), `planned` (the other nine).
- `uiDictionary: true` means `src/i18n/<code>.json` exists with the full key set. A test checks that the file exists exactly when this flag is set, and that the file is registered in `index.ts`. Every dictionary with this flag gets all parity and text-rule tests, even while `enabled` is still `false`.
- `hreflang` (`af-ZA`) is also used for `<html lang>` and `Intl.PluralRules`.

## Using strings

In `.astro` frontmatter:

```ts
import { useTranslations } from '../../i18n';
const tr = useTranslations(locale);
tr('nav.skipLink'); // "Skip to main content"
tr('nav.next', { title: doc.title }); // "Next: Tax and SARS"
tr('search.results', { count: 3 }); // "3 results"
```

Or directly: `t(locale, 'nav.skipLink')`.

Keys are dot paths, typed from `en.json`. A key that does not exist fails `pnpm typecheck`. Build dynamic keys from typed unions, for example `` t(locale, `nav.sections.${section}.name`) `` where `section` is one of the section ids.

### Parameters are typed

`t`, `useTranslations` and `createTranslator` check the parameters of each key:

```ts
t(locale, 'nav.next'); // type error: needs { title }
t(locale, 'nav.next', { name: 'x' }); // type error: the parameter is called title
t(locale, 'search.results', { count: '3' }); // type error: count must be a number
```

JSON imports have no literal string types, so TypeScript cannot read `{title}` out of `en.json` itself. The names live in a generated `interface ParamNames` block in `src/i18n/index.ts`, between `// @generated-start param-names` and `// @generated-end param-names`. A test in `tests/unit/i18n.test.ts` fails when the block is out of date. To regenerate it:

```sh
pnpm exec cross-env I18N_UPDATE_TYPES=1 vitest run --project unit tests/unit/i18n.test.ts -t ParamNames
pnpm exec prettier --write src/i18n/index.ts
```

Keys without placeholders accept an optional params object, but `count` must still be a number.

### Accessible names for repeated controls

When a control appears many times on one page (copy-link buttons in the glossary, "Read" on every step card, copy buttons on prompts), use the short key for the visible text and the `…Named` or `…To` key for `aria-label`, so a screen reader list of buttons is not a list of identical names:

```astro
<button aria-label={tr('glossary.copyLinkTo', { term: entry.term })}>{tr('glossary.copyLink')}</button>
```

Pairs include `doc.copyLink`/`doc.copyLinkTo`, `glossary.copyLink`/`glossary.copyLinkTo`, `sources.copyLinkTo`, `doc.hiddenShow`/`doc.showHiddenNamed`, `doc.showHiddenSections`, `doc.show`/`doc.showNamed`, `templates.open`/`templates.openNamed`, `myPath.read`/`myPath.readStep`, `myPath.markDone`/`myPath.markDoneNamed`, `myPath.markNotDone`/`myPath.markNotDoneNamed`, `prompts.copy`/`prompts.copyNamed`, `prompts.fillFromProfile`/`prompts.fillFromProfileNamed`, `prompts.undoFill`/`prompts.undoFillNamed`, `prompts.showFull`/`prompts.showFullNamed`, `prompts.showLess`/`prompts.showLessNamed`, `common.close`/`common.closeNamed`, `common.dismiss`/`common.dismissNamed`, `home.businessTypes.openType`.

### Client scripts

Custom elements cannot import the whole dictionary without adding weight. Serialise only the groups they need:

```astro
---
import { pick } from '../../i18n';
const strings = pick(locale, ['search', 'prompts']);
---
<st-search data-locale={locale} data-strings={JSON.stringify(strings)}></st-search>
```

```ts
import { createTranslator, type Dict } from '../../i18n';
const strings = JSON.parse(this.dataset.strings!) as Pick<Dict, 'search' | 'prompts'>;
const tr = createTranslator(locale, strings);
tr('search.results', { count: hits.length });
```

`createTranslator` only accepts keys from the picked groups. A client script that imports only `createTranslator` does not bundle the dictionaries: Vite tree-shakes them. A minified probe build was about 3.8 KB raw and 1.4 KB gzip, with no dictionary strings in it.

### Placeholders

- Written as `{name}`: a letter, then letters, digits or `_`.
- Values are inserted with `String(value)`. Numbers are not regrouped, so years and counts stay as typed. Format amounts first with `formatRand` or `formatNumber`, and dates with `formatDate`.
- A missing parameter leaves `{name}` in the text and warns in dev.
- Every language must use exactly the same placeholder names per key. Word order may change. For plural keys the names are compared across all forms together, so a language may leave `{count}` out of one form (for example "Een resultaat").
- Figures that can change (the VAT rate, a year, a threshold, the number of questions) are always parameters: `"VAT ({rate}%)"`, `"Three numbers that changed in {year}"`. A test fails when an English string contains a digit outside a placeholder. The only exception is the part name "Part A2".

### Plurals

A plural value is an object whose keys are CLDR plural categories (`zero`, `one`, `two`, `few`, `many`, `other`). `other` is required.

```json
"results": { "one": "{count} result", "other": "{count} results" }
```

- Pass `count` as a number: `t(locale, 'search.results', { count: 1 })`. The type requires it.
- The form is chosen with `Intl.PluralRules(hreflang)`. A missing category falls back to `other`.
- Each locale must include every category its language needs (a test reads them from `Intl.PluralRules`), and the same categories as English. English and Afrikaans both use `one` and `other`.
- A group object must never have a key called `other`. That key marks a plural.

### Fallback

If a key is missing in a non-English dictionary, or has the wrong shape (a string where English has a plural), `t` and `pick` use English. In dev, and in tests, `console.warn` names the key. Production builds are silent. The parity test makes this a safety net, not a normal state.

## Formatting

All formatters take a locale for symmetry. Numbers and amounts use one format in every language, because Afrikaans keeps numbers byte-identical to English.

| Function                                  | Example             |
| ----------------------------------------- | ------------------- |
| `formatDate('en', '2026-09-13')`          | `13 September 2026` |
| `formatDate('af', '2026-03-01')`          | `1 Maart 2026`      |
| `formatDate('en', '2026-09-13T22:30:00Z')` | `14 September 2026` |
| `formatRand('en', 1234.56)`               | `R 1 234.56`        |
| `formatRand('af', -50)`                   | `-R 50.00`          |
| `formatNumber('af', 2300000)`             | `2 300 000`         |

- **Rand**: `R`, a space, thousands grouped with spaces, `.` before the cents, always two decimals, rounded half away from zero (1.005 becomes 1.01). Both spaces are no-break spaces (U+00A0) so an amount never wraps across lines on a printed invoice. Negative amounts are `-R 50.00`. Amounts above `MAX_RAND_AMOUNT` (`Number.MAX_SAFE_INTEGER / 100`, about R90 trillion) throw `RangeError`, because cents are no longer exact. Tests compare with ` `.
- **Numbers**: same grouping and decimal mark, no fixed decimals unless you pass `minimumFractionDigits` or `maximumFractionDigits`. Minus zero shows as `0`.
- **Dates**: month names and word order come from the dictionary (`date.months.1` to `date.months.12`, `date.format`), so the output does not depend on the ICU data of the browser. Input is `YYYY-MM-DD`, or an ISO timestamp with `Z` or an offset (`+02:00` or `+0200`), which is shown as the calendar day in South Africa (UTC+02:00, no daylight saving). There is no fallback output: anything else throws `RangeError`. That includes impossible dates in either form (`2026-02-30`, `2026-02-30T10:00:00Z`), hours from 24 up, a lower-case `z` and a missing time zone.
- Non-finite numbers throw `RangeError`.

## Routes

Pages live in `src/pages/[...locale]/…`.

```ts
import { localeStaticPaths } from '../../lib/i18n-routes';
export const getStaticPaths = () => localeStaticPaths();
// [{ params: { locale: undefined }, props: { locale: 'en' } },
//  { params: { locale: 'af' }, props: { locale: 'af' } }]
```

Routes with more params combine these with their own entries.

- `alternateUrls(route, availableLocales, site, base?)` returns `{ hreflang, href, locale }[]` with absolute URLs for every available enabled locale, plus `x-default` pointing to English when English is available. Pass the locale-independent route (`core/register/`). A locale prefix on the route (`af/core/register/`) is removed, so it is never doubled. Query and hash are dropped. Unknown and disabled codes are ignored. Any path on `site` is ignored. A full URL as `route` throws `RangeError`.
- `switchLocaleUrl(current, targetLocale, base?)` returns the same page in the other language as a path, and keeps the query string and hash. `current` may be `location.pathname + location.search + location.hash`, `location.href` or a `URL`. Repeated slashes in the path are collapsed first. A relative path such as `core/register/`, and a scheme other than `http:` or `https:`, throw `RangeError`. The language switcher uses it for plain links. It never redirects.

## Text rules (enforced by `tests/unit/i18n.test.ts`)

- Every dictionary with `uiDictionary: true` has exactly the English keys. Missing and extra keys both fail, with a list of each.
- No empty strings, no leading or trailing spaces, no double spaces, no line breaks.
- No straight quotes or apostrophes (`"` and `'`). Use “ ” and ’. Afrikaans writes ’n with U+2019. This keeps strings safe in HTML attributes and consistent in print.
- No exclamation marks and no `...`. Use the single character `…` for "loading" states.
- Braces appear only as `{param}` placeholders.
- English strings contain no figures outside placeholders (see Placeholders). Digits are byte-identical to English per key.
- Fixed names stay verbatim (SARS, CIPC, POPIA, Pty Ltd, BizPortal, eFiling, PayShap, PAYE, PDF, JavaScript).
- Fixed Afrikaans terms are checked outside text in “quotes”. Quoted text is a literal, for example the legal words “Tax Invoice”, and stays in English.
- Length: every English string of at most 24 characters counts as a label. The translation fails when it is more than 1.6 times the English length and at least five characters longer. Exceptions are listed per locale in `LABEL_LENGTH_EXCEPTIONS` in the test, each with a reason. A new language starts with none. A test fails when one of a locale's own exceptions is no longer needed. The design allows about +25% for all text.

### Strings that mirror content headings

Some UI strings repeat a heading from the markdown documents. The markdown is the source of truth: the English string must match the English heading exactly, and the Afrikaans string must match the heading in `docs/rsa-business-toolkit-af/`. If a heading changes, change the string in the same commit, and the other way round.

| Key                                                                      | English heading (`docs/rsa-business-toolkit/`)                    |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| `checklist.title`                                                        | `05 Look it up/02-master-checklist.md` H1 "Master checklist"      |
| `checklist.keyToShortWords`                                              | same file, "Key to the short words"                               |
| `checklist.parts.a`, `.a2`, `.b`, `.c`, `.d`                             | same file, the "Part A" to "Part D" headings                      |
| `doc.wordsUsed`                                                          | "Words used in this file", the first H2 in the documents that have one |

The Afrikaans content tree does not exist yet. Until it does, the Afrikaans strings are the agreed wording, and the Afrikaans headings must use it.

Tone, from the toolkit itself: short sentences, plain words, no jargon, no idioms, no exclamation marks. Readers may use English as a second language and may never have run a business.

## Add a key

1. Add it to `src/i18n/en.json` in the group for its area. Use camelCase for names, and the app's ids for keys that map to data (`business-types`, `sole-prop`, `pty-growing`). Never name a key `other` inside a group.
2. Add the same key to `src/i18n/af.json` (and every other file with `uiDictionary: true`).
3. If the key has `{param}` placeholders, or you changed them, regenerate `ParamNames` (see "Parameters are typed").
4. Run `pnpm exec vitest run --project unit tests/unit/i18n.test.ts` and `pnpm typecheck`.
5. Commit the English and Afrikaans change together with scope `i18n`.

To rename or remove a key, change every dictionary in the same commit, regenerate `ParamNames` and search `src/` for the old key.

## Add a language

Example: isiZulu (`zu`). Steps 1 and 2 go in one commit, and typecheck and test cleanly while `enabled` is still `false`.

1. **Dictionary**: copy `en.json` to `src/i18n/zu.json` and translate every value. Keep keys, placeholders, digits and plural categories. Add any plural categories the language needs (the test lists them). Translate `lang.names` and `date.months`, and set `date.format` word order.
2. **Register it**: in `src/i18n/locales.ts` set `uiDictionary: true` for `zu`. Keep `enabled: false` and `status: 'planned'`. In `src/i18n/index.ts` import the file and add it to `DICTIONARIES`:

   ```ts
   import zu from './zu.json';
   const DICTIONARIES: Readonly<Partial<Record<LocaleCode, DictTree>>> = { en, af, zu };
   ```

   `pnpm test` now checks `zu.json` for key parity, placeholders, plural categories, digits, text rules and label length. A new language has no label-length exceptions. If a label really cannot be shorter, add it under `zu` in `LABEL_LENGTH_EXCEPTIONS` in `tests/unit/i18n.test.ts`, with a reason. Run `pnpm typecheck` and `pnpm test` before you commit.

3. **Content mirror tree**: create `docs/rsa-business-toolkit-zu/` with the same file names as the English tree, with a style guide and terms file like the Afrikaans ones. Run `pnpm content:fidelity --lang zu` until it is clean, then `pnpm content:build`.
4. **Enable routing**: set `enabled: true` and the right `status` (`partial` until every document is reviewed). `Locale` now includes `'zu'`, so `t('zu', …)` typechecks. `astro.config.ts` picks up `i18n.locales` automatically, and `localeStaticPaths()` emits `/zu/` pages. Update the tests that pin the enabled list to `['en', 'af']` (`pnpm test` names them: for example "enables only English and Afrikaans", "builds the sitemap locale map", `localeStaticPaths` and `paths` "comes from src/i18n/locales.ts"). Tests that need a planned locale as an example take the first locale with `enabled: false`, so they keep working.
5. **Sitemap**: `sitemapLocales()` adds `zu: 'zu-ZA'` automatically. Check `dist/sitemap-0.xml` after `pnpm build`.
6. **Check**: `pnpm gate:fast`, then the language switcher, `<html lang="zu-ZA">`, hreflang links and the machine-translation notice on a few pages.

Fonts already include latin-ext, so Tshivenḓa letters (ḓ ḽ ṅ ṋ ṱ) render.

## Numbers, codes and URLs stay verbatim

In UI strings and in documents, never translate or reformat:

- digits, percentages and rand amounts (`R2.3 million` becomes `R2.3 miljoen`: the figure stays, the word changes);
- form codes and references (ITR12, ITR14, IRP6, EMP201, EMP501, VAT101, VAT264, SAPS 601, CoR 14.3, CoR 40.5, R638, R146);
- URLs, email addresses and domain names;
- act names (`Companies Act 71 of 2008`).

Pass values in through `{param}` placeholders rather than writing them into dictionary strings, so they come from the same data in every language.
